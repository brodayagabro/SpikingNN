# CPG с афферентами: обучение периодическому движению

Это адаптация **схемы связей Markin et al., 2010** на 10 спайковых нейронах
Ижикевича, с `OneDOFLimb`, `SimpleAdaptedMuscle` и афферентами SpikingNN.
Ионные уравнения, Hill-мышцы и контакт с опорой исходной статьи не воспроизводятся.
Источник: [Afferent control of locomotor CPG](https://pmc.ncbi.nlm.nih.gov/articles/PMC5323435/),
DOI 10.1111/j.1749-6632.2010.05435.x, Figure 1 и Table 1.

Выполненный sweep, лучший геном, графики и измеренная зависимость от
тонического входа описаны в [RESULTS.md](RESULTS.md).

## Запуск

Работайте из `SpikingNN/scripts/CPG_afferents_control` в окружении `CPG`:

```bash
conda activate CPG
python -m unittest -v test_training
python train.py verify
python train.py sweep --populations 20 50 --seeds 11 29 --generations 150 --workers 6 --output runs/pilot_sweep
```

Зависимости: Python >=3.10, NumPy, Numba, Matplotlib, jsonschema, tqdm.
При необходимости: `python -m pip install numpy numba matplotlib jsonschema tqdm`.
API подключается из `src/SpikingNN` текущего checkout. Обучение не зависит от
файлов `AfferentBalance2026` и не входит в пакетную команду обучения SpikingNN.

`--workers` задаёт число потоков оценки популяции. Sweep последовательно
выполняет четыре запуска: N=20/50 × seed=11/29, по 150 поколений каждый.
Поколение 0 — оценка исходной популяции; далее идут 150 поколений потомков.
Итого в этом sweep 21 140 оценок особей, включая исходные популяции.
Каталог результата должен быть новым: законченный опыт не перезаписывается.

Отдельное обучение и повторный запуск найденного генома:

```bash
python train.py train --population 30 --generations 150 --seed 11 --workers 6 --output runs/my_run
python simulate.py --genome runs/my_run/best_genome.json --duration 20 --output runs/my_run/api_dynamics.png
python train.py scan --genome runs/my_run/best_genome.json --output runs/my_drive_scan
python simulate.py --genome runs/my_run/best_genome.json --drive 1.2 --output runs/my_run/drive_1p2.png
```

Для возобновления прерванного **отдельного** обучения повторите исходную команду
`train` с `--resume`. Конфигурация, планируемое число поколений и исходный код
должны оставаться прежними. Контрольная точка сохраняется каждые 10 поколений
и в конце; она содержит популяцию, оценки, историю и состояние генератора случайных чисел.

## Что получает сеть и что считается целью

По умолчанию эталон:

```text
q*(t) = 90° + 10° sin(2π × 1 Hz × t + 0)
```

`q=90°` соответствует нижней вертикали. Старт: `q=90°`, скорость 0,
мышцы и синаптические токи 0, `V=c`, `U=b*c`. Стартовая скорость эталона
отличается от скорости конечности; первые 2 s исключены из оценки, но система
всё это время интегрируется непрерывно.

**Синусоида используется только при расчёте фитнесса.** Она не поступает
в сеть, мышцы, афференты или механику. Нейронный вход:

```text
I = Q_app[:, 0] × d1 + Q_app[:, 1] × 1 + Q_aff @ afferents
```

`d1` постоянен на всём интервале. Он действует на RG-F/E и PF-F/E.
Отдельный тонический вход интернейрона In (`d2`) остаётся равным 1.
В обучении меняются коэффициенты этих проекций; внешней периодической команды нет.

Частоту, амплитуду и фазу **цели обучения** можно изменить командой:

```bash
python train.py train --frequency 0.5 --amplitude 15 --phase 1.5707963267948966 --drive 1 --output runs/half_hz
```

`--frequency` — Hz, `--amplitude` — градусы, `--phase` — радианы при `t=0`.
Эти ключи не являются ручками мгновенного задания частоты готовому CPG.
Параметры времени, среднего угла и штрафов находятся в `training.json`:

| Поле `task` | Назначение | По умолчанию |
|---|---|---:|
| `frequency_hz` | Частота эталона | 1 |
| `amplitude_deg` | Амплитуда относительно среднего | 10 |
| `center_deg` | Средний абсолютный угол | 90 |
| `phase_rad` | Фаза эталона относительно начала симуляции | 0 |
| `duration_s` | Длительность обучения на одной особи | 10 |
| `score_start_s` | Начало окна фитнесса, без сброса состояния | 2 |
| `velocity_weight` | Вес ошибки скорости | 0.15 |
| `angle_limit_deg` | Допустимое отклонение от нижней вертикали | 85 |
| `tonic_drive` | Постоянный множитель `d1` | 1 |

Окно фитнесса — `[score_start_s, duration_s)`; оно должно содержать минимум
два периода. Для низких частот увеличьте `duration_s` и
`evaluation.long_duration_s`. Угол ограничивается критерием пригодности особи,
а не механическим упором. В `system.json` времена задаются в **ms**,
в `training.json` и CLI длительности — в **s**. Шаг интегрирования фиксирован
на 0.1 ms: в текущем API он влияет также на площадь спайкового импульса.

## Фитнесс и генетический алгоритм

Пусть `A` — амплитуда в радианах, `ω=2πf`. Максимизируется

```text
fitness = 1 / (1 + mean(((q-q*)/A)^2)
                  + velocity_weight × mean(((w-w*)/(A×ω))^2))
```

У идеальной траектории фитнесс 1. Положение без движения в центре синусоиды
имеет RMSE `A/sqrt(2)`: для цели ±10° это 7.071°. Это полезный контроль,
чтобы не принять почти неподвижную конечность за решение задачи.
Расхождение чисел, выход за допустимый угол или преждевременное завершение
дают фитнесс −1. Эталон не сдвигается по времени и не подгоняется к выходу.

Оценка популяции использует Numba с сохранением шага и порядка обновлений API;
ошибки измеряются каждые 1 ms. Все финальные победители пересчитываются
через **настоящий SpikingNN API**, где итоговый фитнесс измеряется на каждом
шаге 0.1 ms. Итоговый победитель sweep выбирается по этому API-фитнессу
на исходном окне обучения. Из-за чувствительности спайковой динамики
округление может раздвинуть моменты спайков на длинных интервалах; в
`metrics.json` сохраняются и оценки Numba, и оценки API, и расхождение угла.
`verify` строго проверяет все состояния на первой секунде и сообщает ошибки
на всём проверяемом интервале. Поэтому одного короткого теста недостаточно
для утверждения о полном совпадении длинных траекторий.

Алгоритм использует:

- вещественную хромосому в `[0,1]`, линейные и логарифмические шкалы;
- сохранение лучших `ceil(0.05 × N)` особей;
- турнирный отбор по три кандидата;
- арифметическое скрещивание с коэффициентами от −0.15 до 1.15;
- гауссову мутацию каждого гена с вероятностью 0.25;
- косинусное снижение её стандартного отклонения с 0.12 до 0.004;
- 5% вероятности случайного иммигранта при рождении потомка;
- отражение вышедших за границы генов обратно в `[0,1]`.

Начальная популяция содержит исходный геном, близкие мутации, 20% случайных
особей и три явно заданных пробных варианта с более медленной адаптацией RG
и увеличенной силой разгибателя. Их параметры находятся в
`SearchSpace.initial_candidates()`; они не являются заранее обученными решениями.

По умолчанию обучаются **22 группы** в `training.json → search.groups`.
`absolute` задаёт общее физическое значение перечисленным параметрам;
`multiply` умножает их исходные значения на общий положительный коэффициент.
Группы не пересекаются, знаки связей сохраняются. `--space all` включает
независимый поиск по всем 95 параметрам исходного генома. Полный экспорт
в обоих случаях совместим с `simulate.py`.

## Частота, амплитуда и фаза

В исходной работе Markin увеличение нисходящего драйва повышало скорость
ритма и амплитуду движения (раздел **Control of locomotor speed**, Figure 4).
В спайковой адаптации такую зависимость нужно измерять: возможны насыщение,
смена режима, подавление одного полуцентра и немонотонная зависимость.

| Что менять | Имена групп / параметров | Основное действие |
|---|---|---|
| Нисходящий тонический вход | `--drive`, `task.tonic_drive` | Совместно меняет возбуждение RG и PF; влияет на частоту, силу и среднюю позу |
| Адаптацию генератора | `RG_a`, `RG_d` | Времена восстановления и прекращения пачек; сильное влияние на период |
| Возбудимость RG | `RG_b`, `RG_c`, `drive_RG_F/E` | Порог генерации, пачечный/тонический режим, симметрия фаз |
| Взаимное торможение | `inhibition_gain`, `tau_inh_ms` | Переключение полуцентров, длительность фаз и чередование |
| Возбуждающие синапсы | `RG_to_In_gain`, `RG_to_PF_gain`, `tau_exc_ms` | Передача пачек, длительность возбуждения и устойчивость ритма |
| Выход к мотонейронам | `drive_PF`, `motor_gain`, `PF_to_Inab_gain` | Сила/скважность мышечной активации; амплитуда и смещение движения |
| Мышечные коэффициенты | `flexor_A`, `extensor_A`, `muscle_w` | Масштаб и баланс сил; амплитуда и средний угол |
| Времена мышц | `muscle_tau_c_ms`, `muscle_tau_force_ms` | Фильтрация пачек, задержка силы и частотная характеристика |
| Афференты | `length_afferent_gain`, `force_afferent_gain` | Коррекция фаз по растяжению/скорости/нагрузке; частота и амплитуда связаны |
| Механика (фиксирована при поиске) | масса, длина, вязкость, геометрия | Инерция, момент силы, резонанс; собственная частота свободной малой осцилляции здесь около 1.11 Hz |

Высота отдельного спайка на выходе API фиксирована (30). «Амплитуда CPG»
в этом опыте означает структуру пачек/частоту разрядов, а амплитуда движения
возникает после фильтрации мышцами и механикой. Эти величины не следует смешивать.
Один скаляр `d1` обычно не позволяет независимо задать и частоту, и амплитуду.

**Абсолютная фаза автономного генератора зависит от начальных условий.**
Оптимизация под фиксированную фазу здесь имеет смысл для фиксированного
сброса состояния. Она сама по себе не обеспечивает захват внешней фазы после
возмущения. Для такого свойства понадобится отдельный механизм фазового сброса
или синхронизирующий вход, а затем отдельный эксперимент на устойчивость.

## Файлы и результаты

| Файл | Назначение |
|---|---|
| `system.json` | Исходная система в формате SpikingNN API |
| `genome.json` | Необученный исходный геном, 95 значений и диапазонов |
| `simulate.py` | Расчёт непосредственно через API, `--drive`, `--no-feedback`, PNG |
| `dynamics.py` | Ускоренный шаг, упаковка параметров, сброс и запись состояния |
| `fitness.py` | Эталон, фитнесс, параллельная оценка, спектральные и фазовые показатели |
| `evolution.py` | Генетический алгоритм и воспроизводимое возобновление |
| `train.py` | Команды `train`, `sweep`, `verify`, `scan`; сохранение результатов |
| `training.json` | Траектория, временные окна, GA, диапазоны 22 групп, sweep драйва |
| `test_training.py` | API-сверка, фитнесс фазы, экспорт генома, потоки, resume |

В каждом запуске сохраняются `best_genome.json`, `history.csv`,
`checkpoint.npz`, `metrics.json`, `tracking.npz`, `tracking.png`, копии входов,
`manifest.json` с версиями и хэшами, `source_snapshot.zip`.
В `tracking.npz` основной `trace` финального результата получен через API;
`numba_trace` сохраняется отдельно для проверки. Заголовки колонок вложены в NPZ.

В корне sweep находятся `summary.csv`, `selection.json`, `best_genome.json`
и общая фигура `sweep.png`. `drive_scan/response.csv` и `response.png` показывают
измеренные через API частоту/амплитуду для замороженного генома при разных `d1`.
Каждый режим драйва начинается с одинаковых начальных условий; оценивается
интервал 5–20 s. Доминирующий спектральный пик не всегда является основной
частотой: сигнал может содержать гармоники и нерегулярные пачки. Разрешение
частот ограничено длительностью окна, даже при дополнении FFT нулями.

По умолчанию обученный геном также запускается на 20 s. Интервал 10–20 s
продолжает ту же траекторию **без сброса** и не участвует в выборе победителя.
Это проверка сохранения фазы на более длинном горизонте, не независимая
проверка устойчивости к новым начальным состояниям или внешним воздействиям.
