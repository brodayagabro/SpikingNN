# D — слежение за меняющимся целевым углом

[English](README.en.md)

В C уже обучено отображение желаемого угла в два входных тока. D проверяет,
может ли тот же контроллер следовать непрерывно меняющемуся положению.
Механическая система воспроизводит угол с некоторой ошибкой и запаздыванием;
наличие полинома токов само по себе не гарантирует точного слежения.

```text
целевой угол → два полинома → [фильтр токов] → нейроны → мышцы → конечность
                                                ↑         ↓        ↓
                                                └──── полные Afferents
```

Измеренный угол, скорость и ошибка слежения не входят в закон задающих токов.
ПД/ПИД-регулятора нет. Нейроны получают прежнюю нелинейную обратную связь
Ia/II/Ib. Все симуляции используют шаг **0,1 мс**, физику без множителя ×10,
фиксированные `A=0.37`, `a1=0.2`, `a2=0.05` и мышечные времена ≥5,1 мс.

## Класс с входным углом

[controller.py](controller.py) содержит `AngleController`. Пример из корня репозитория:

```python
from scripts.AfferentBalance2026.experiments.D_trajectory import AngleController

controller = AngleController(
    "scripts/AfferentBalance2026/experiments/D_trajectory/results/best_genome.json",
    initial_angle_deg=-30,
    initial_velocity_rad_s=0.2,
    target_angle_deg=0,
)
state = controller.advance(target_angle_deg=15, duration_s=0.01)
print(state["angle_deg"], state["input_currents"])

controller.target_angle_deg = 20  # Change the command; keep all physical state.
state = controller.step()         # Advance exactly 0.1 ms.
```

Можно передать непосредственно объединённый `best_genome.json` из C: квадратный
полином дополняется нулевыми кубическими коэффициентами. Внешние углы заданы
в градусах относительно неустойчивой вертикали, скорости — в рад/с, время —
в секундах. Команда ограничена откалиброванным диапазоном −45…45°; значения вне
его вызывают исключение, а не скрытое насыщение.

- `step(angle)` делает один шаг 0,1 мс; угол можно не передавать.
- `advance(angle, duration_s)` удерживает команду на блоке шагов, например 10 мс.
- `target_angle_deg = angle` меняет только команду, не продвигая время.
- `snapshot()` возвращает копии наблюдаемых переменных, включая токи, потенциалы,
  силы, кальций, активации, афференты и синаптические токи.
- `reset(...)` явно сбрасывает всю историю. После падения за ±90° или
  нечислового состояния расчёт останавливается; для продолжения нужен `reset`.

Между командами сохраняются **все** состояния нейронов, синапсов, мышц,
афферентов и конечности. Это интерфейс подачи команд в ходе моделирования;
планирование по настенным часам и гарантии аппаратного реального времени
в него не входят. Первый вызов может компилировать Numba; перед внешним циклом
можно сделать пробный шаг и `reset`.

Для произвольного сигнала, обновляемого каждые 10 мс:

```python
import numpy as np

controller.reset(target_angle_deg=0)
history = []
for k in range(6000):
    t = k * 0.01
    target = 30 * np.sin(2 * np.pi * t / 20)
    state = controller.advance(target, 0.01)
    history.append(state)
    if state["failure"] != "none":
        break
```

Это пример ступенчатого обновления команды; научный пакетный расчёт D
обновляет гладкую функцию на каждом внутреннем шаге 0,1 мс.

## Анимация с ползунком: одна самостоятельная ячейка

В конце [explore_genome.ipynb](explore_genome.ipynb) находится ячейка
`LIVE_ANGLE_SIMULATION`. Её можно выполнить сразу в ядре `spikingnn`, без
предыдущих ячеек. Все импорты, настройки, класс `LivePendulumSimulation`,
обработчики кнопок и запуск расположены в этой ячейке. Дополнительные файлы
для интерфейса не нужны; физику считает существующий `AngleController`,
загружающий `results/best_genome.json`.

- Ползунок −45…45° задаёт направление зелёной пунктирной прямой. Тёмный отрезок
  показывает фактическое положение конечности. Положительные углы направлены
  вправо от верхней вертикали.
- Красная нить — сгибатель, синяя — разгибатель. Коричневая стрелка `mg`
  направлена вниз из центра однородного звена. Цветные стрелки мышц показывают
  **натяжение вдоль нитей к неподвижным креплениям**. Длины нитей соответствуют
  геометрии модели. Подписаны силы и моменты с их знаками; длина стрелок
  масштабируется и ограничивается только для наглядности.
- Справа показаны целевой и фактический углы за последние **10 секунд**.
  Команда и история обновляются каждые 10 мс, интегрирование — каждые 0,1 мс.
- **Стоп / Старт** замораживает и продолжает то же состояние; пауза не
  засчитывается в модельное время. **Сброс** возвращает исходные угол и
  скорость, очищает историю и сохраняет текущее значение ползунка.
- **Снимок PNG** останавливает расчёт и сохраняет оба графика с высоким
  разрешением в `results/live_snapshots/`. Путь выводится под анимацией.
  Для обычного снимка экрана также достаточно нажать **Стоп**.

В начале этой же ячейки можно изменить `FONT_FAMILY`, `FONT_SIZE`, `TITLE_SIZE`,
`LABEL_SIZE`, `TICK_SIZE`, `LEGEND_SIZE`, `ANNOTATION_SIZE`, `WIDGET_FONT_SIZE`.
Также доступны исходные условия, путь к геному, частота кадров `FPS`,
размер рисунка `FIGSIZE`, разрешения `FRAME_DPI`/`SNAPSHOT_DPI`, масштаб стрелок
и каталог снимков. `GRAVITY_MIN_ARROW_M=0.06` задаёт минимальную видимую длину
стрелки тяжести в координатах рисунка; физическое значение `mg` не изменяется.
После изменения настроек ячейку нужно выполнить повторно:
прежняя фоновая задача закрывается, создаётся новая симуляция.

По умолчанию `AUTO_START=True`, `TIME_SCALE=1`: анимация запускается сразу и
следует настенным часам. Асинхронный цикл оставляет ядро доступным для кнопок.
При медленной отрисовке возможно отставание; физические шаги не пропускаются.
Выход за ±90° останавливает расчёт и требует явного сброса. Математическая
модель, геном и закон токов не изменены для анимации.

## Отдельная тетрадка с активностью нейронов и афферентов

[live_activity.ipynb](live_activity.ipynb) содержит расширенную копию живой
симуляции в **одной кодовой ячейке** `LIVE_ACTIVITY_SIMULATION`. Запустите её
в ядре `spikingnn`.

В начале ячейки `GENOME_VARIANT = "slow_muscle_mirrow"` выбирает зеркальный
геном; другие варианты — `"fast_muscle"`, `"slow_muscle"` и `"current"`
(последний загружает `results/best_genome.json`). При `GENOME_PATH = None`
используется выбранная версия. Можно явно задать
`GENOME_PATH = "best_genome_slow_muscle_mirrow.json"`: короткое имя ищется
в папке D независимо от рабочего каталога Jupyter. Полный путь имеет тот же
приоритет над `GENOME_VARIANT`. Фактический путь выводится при запуске.

Если тетрадка уже открыта, перечитайте её с диска и выполните эту ячейку снова.
Она обновляет связанные загрузчики Python, которые могли остаться в памяти
от версии до введения симметрии: сначала саму служебную функцию, затем
`core.genome`, после него зависимые модули. Такой порядок также устраняет
`ImportError: cannot import name 'MIRROR_INDICES'` в ранее открытом ядре.
Это устраняет воспроизведённую ошибку
`Expected 56 finite coordinates in [0, 1]` при загрузке зеркального D-генома
с 28 независимыми координатами. Полные 60 физических полей сохранены;
переформатировать или дополнять геном нулями не требуется.
[Происхождение трёх версий](GENOME_VERSIONS.md).

- **A** — стержень, мышцы, целевое направление и силы.
- **B** — заданный и фактический угол.
- **C** — потенциалы двух нейронов N0/N1 (мВ) либо растр спайков. Переключатель
  «Нейроны» меняет отображение без сброса динамики.
- **D** — сумма откликов **Ia + II + Ib** отдельно для сгибателя и разгибателя.
  Это единицы модели, не частота в Гц и не взвешенный ток обратной связи.
- **E** — силы сгибателя и разгибателя в ньютонах.

Четыре правых графика имеют общую шкалу времени; длину окна задаёт `WINDOW_S`.
`RecordingAngleController` в той же ячейке использует существующий Numba-интегратор
с записью **каждого шага 0,1 мс**. История потенциалов и сумм афферентов хранится
с этим разрешением в ограниченном окне, времена спайков — без прореживания.
Для скорости отрисовки кривые показываются по минимумам/максимумам временных
интервалов (`MAX_DISPLAY_POINTS`); короткие пики сохраняются. Это изменение
отображения, а не шага модели. N0/N1 обозначают индексы нейронов, а не отдельные
эксклюзивные связи с мышцами.

Сохранены ползунок, старт/стоп, сброс, настройки шрифтов и увеличенная стрелка `mg`.
Снимок включает все пять панелей и сохраняется в `results/live_activity_snapshots/`.
Начальный вид нейронов задаёт `NEURON_VIEW`, размер рисунка — `FIGSIZE`, частоту
кадров — `FPS`. При медленной отрисовке можно снизить `FPS` или `FRAME_DPI`;
модельное время не перескакивает через пропущенные физические шаги.

## Геном и команды

`TrajectoryGenome` содержит **60 физических полей** и **56 независимых координат
без симметрии или 28 с зеркальной симметрией**:
52 поля прежней модели, включая фиксированную геометрию и A, плюс восемь
коэффициентов двух кубических полиномов. Описания всех полей — английские.
Для нейрона i:

`x = target_angle_deg / 45`, `I_desired[i] = Σ(k=0…3) c[i,k] x**k`.

При ненулевой постоянной фильтра `tau`:
`I[n] = I[n−1] + (1 − exp(−0.0001/tau)) (I_desired[n] − I[n−1])`.
При `tau=0` ток сразу равен команде. Начальный ток равен полиному начальной
цели. Постоянная фильтра — гиперпараметр, не дополнительный ген.
Токи сохраняются в единицах модели; имена полей `*_nA` унаследованы от C.

## Протокол обучения

Конфигурация — [genome_cfg.json](genome_cfg.json). Используются четыре сохранённых
победителя C: `joint` и `staged` из серий `joint_sweep_20261022` и
`joint_sweep_tau_gt5_20261022`. У всех импортируемых геномов проверяются новые
границы и механика. Исходные результаты C сохраняются без изменений.

1. Сравниваются четыре исходных генома и фильтры 0 / 0,1 / 0,5 с по валидации.
2. Из лучшего сочетания запускаются два обучения: `command_only` изменяет восемь
   коэффициентов, `joint` — все 56 свободных координат. Общий ГА берётся из core.
3. Каждое обучение: 30 особей × 80 эпох, seed 44, вероятность мутации каждого
   гена 0,1; σ плавно меняется 0,04→0,004 в нормированных координатах.
   Начальная популяция близка к исходному решению (σ=0,012).
4. Валидация всех особей выполняется на эпохах 1/20/40/60/80. Исходный геном
   участвует как эпоха 0, поэтому победитель может остаться без дообучения.
5. Общий победитель выбирается по валидации **до** расчёта независимого теста.

Банки содержат 8 учебных, 10 валидационных, 18 тестовых траекторий. Независимые
seed: 2026102301/02/03. Синусоиды: амплитуды 10…45°, частоты 0,04…0,10 Гц,
случайные фазы и смещения при сохранении всей команды внутри ±45°. Начальные
углы −45…45°, скорости −0,5…0,5 рад/с. Два учебных примера фиксированы:
амплитуда 45° / период 20 с и 30° / 10 с. Банки сохраняются целиком.

Каждый эпизод: 4 с удержания начальной цели, 2 с плавного включения синусоиды
через полином `6u⁵−15u⁴+10u³`, затем не менее двух полных периодов. Состояние
системы не сбрасывается при смене направления или периода. Для независимой
диагностики используются амплитуды 15/30/45° × периоды 10/20/40 с; период 40 с
лежит вне учебного диапазона и не используется при выборе генома.

## Оценка качества

Из оценки исключаются первые 4 с захвата начальной цели. Ошибки считаются
относительно **меняющихся** желаемых угла и аналитической угловой скорости:
`e=theta−theta_target`, `ev=omega−omega_target`.

Оценка эпизода:

`0.10 survival_fraction + 0.55 mean(exp(−(e/5°)²))`
`+ 0.20 mean(exp(−(ev/0.15 rad/s)²)) + 0.15 in_band_fraction`.

Полоса: `|e|≤3°` и `|ev|≤0.35 рад/с`. Успех требует полного горизонта,
не менее 95% времени в полосе и RMSE≤3°. Недостающие после падения отсчёты
дают нулевую награду; знаменатель остаётся полным плановым числом шагов.
RMSE рассчитана по фактически наблюдаемой части, поэтому она всегда
рассматривается вместе с признаком падения и временем выживания.
Общий фитнесс из core: 0,5 среднего + 0,3 среднего худшей четверти + 0,2 минимума.
Статический критерий установления C заменён критерием слежения D.

Для `frozen/`, `command_only/`, `joint/` записываются `test/` (18 траекторий) и
`diagnostics/` (9 траекторий), включая падения. Каждый NPZ содержит `trace`
(26 каналов), `reference` (целевые угол и скорость), `commands` (два приложенных
и два желаемых тока), параметры, метрики и имена столбцов. Запись полная,
**каждые 0,1 мс**, включая reset. Ток в строке n>0 приложен на интервале,
который заканчивается в этой строке; его целевой угол берётся из строки n−1.
`figures/` содержит сравнение слежения, RMSE по амплитуде/периоду, фазовые
траектории и состояния одного общего примера (30°, период 20 с).
Результаты вычислений исключены из Git. Один seed и конечные траектории
не устанавливают глобальной устойчивости или статистического превосходства.

## Проверки реализации

`tests/test_trajectory.py` проверяет непрерывность скрытого состояния, смену
команд без reset, единицы фильтра, воспроизведение динамики исходными классами
библиотеки при переменных токах, аналитическую скорость цели, разделение банков,
независимый пересчёт метрик, фиксированные параметры, сохранение поколений,
выбор с учётом эпохи 0 и совпадение последовательного/параллельного расчёта.
Постоянная команда также сверена с прежним решателем по всем каналам;
сохранённый десятисекундный пример C воспроизведён побитово.
