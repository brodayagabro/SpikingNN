## Расширение модели

Текущая архитектура — `two_neurons_one_limb_v1`, схема контроллера — `afferent_controller_52_v4`.
JSON меняет существующие области/fixed-поля/связи, но не смысл и размер этой схемы.
Для большего числа нейронов или MultyLimbSystem:

1. Определите новый versioned-кодек с именами физических полей, encode/decode/size/names, единицами состояния и каналов.
2. Реализуйте численный адаптер и банки в границе `make_task`/`ExperimentTask`; там остаётся специфика динамики и управляющего входа.
3. Дополните явную диспетчеризацию схем config/artifacts; старые 52 поля нельзя переинтерпретировать как другую систему.
4. Используйте общий исполнитель, детерминированный GA, snapshots, стадии, выбор и сохранение.
5. До научного запуска проверьте физический шаг по соответствующим классам SpikingNN, направления сил, единицы, сетку времени,
   непрерывность скрытого состояния, метрики по плотным траекториям, round trip генома, воспроизводимость популяций и порядок процессов.

Реестр плагинов и сложная иерархия классов не вводились. A/B/C/D обслуживаются явными небольшими адаптерами.
Экспорт выводит размер физических массивов из кодека; текущие каналы и банки остаются спецификой модели.
Большая сеть/многозвенный интегратор — точка расширения, **не реализованная и не проверенная новая научная модель**.

## Профилирование фиксированного протокола

Одинаковое окружение, 6 особей × 4 эпизода × 0,05 с; 7 повторов после прогрева; отдельный пустой Numba cache для каждого холодного процесса.
На столь короткой задаче заметны служебные расходы процессов; это не прогноз скорости длинного научного обучения.

| Компонент | Прежний evaluator | Общий evaluator |
|---|---:|---:|
| Холодное интегрирование с JIT | 2,765 с | 2,770 с |
| Медиана прогретого training | 2,107 мс | 2,186 мс |
| Медиана прогретого validation | 2,070 мс | 2,136 мс |
| Первая оценка в 2 процессах со spawn | 0,941 с | 0,948 с |
| Медиана прогретой процессной оценки | 1,724 мс | 2,021 мс |
| IPC-пакет одной особи | 929 байт | 557 байт |
| Медиана записи сжатых массивов | 0,287 мс | 0,244 мс |
| Небольшой рисунок | 30,25 мс | 29,97 мс |

Байты численных метрик имеют одинаковый SHA-256. Общая обёртка добавляет около 0,08 мс последовательно и 0,30 мс
в процессном режиме на этой маленькой задаче; ускорение не заявляется. Запись остаётся вне горячих численных циклов.
Утилита профилирования сохраняет сырые JSON и рисунки.

## Границы совместимости

Исторические Python API обучения оставлены для прежних форматов и регрессии; действующие CLI направлены в общий исполнитель.
Старые результаты, frozen ZIP и научные выводы не мигрировались и не пересчитывались.
`report/build_retraining_article.py` остаётся датированным сборщиком прежней статьи;
новые отчёты строятся командой `run.py report --manifest ...`.
Replay текущей моделью записывается как новый протокол оценки, а не объявляется точным запуском архивного runtime.
Архивные реализации активируются явно в отдельном процессе. После смены численного кода перезапустите Jupyter.

# Разработка и проверка

[English](DEVELOPMENT.en.md) · [Обзор](README.md)

Из корня репозитория:

```bash
.venv/bin/python -m pytest -c scripts/AfferentBalance2026/pytest.ini scripts/AfferentBalance2026/tests -q
.venv/bin/python scripts/AfferentBalance2026/tools/validate_layout.py
```

Тесты сопоставляют Numba с независимым воспроизведением классами библиотеки, проверяют нелинейные рецепторы, все 52 поля и фиксированную геометрию, английские описания, ограничения A/B, банки условий, воспроизводимость процессного пула, сохранение поколений/победителей и sweep. Короткие реальные интегрирования служат проверкой реализации, не результатом научного обучения. Архивные тесты исключены из активного сбора.

Тетрадки используют ядро `spikingnn`. Переменная окружения `SPIKINGNN_NOTEBOOK_SMOKE=1` сокращает их демонстрационные сетки и горизонт для автоматической технической проверки; обычный запуск использует полные значения. Обучение в тетрадках выключено до явного изменения флага.

Изменяйте общую физику только в `experiments/simulation.py` и проверяйте соответствие `SpikingNN.core.Izh_net` по всем каналам. Изменения закона токов относятся к C/D; потоковый интерфейс и сигналы находятся в D. Докстроки и комментарии нового кода, описания полей JSON — английские; документация имеет пару RU/EN. Результаты и снимки исходников не добавляйте в Git.

Старые числовые массивы нельзя интерпретировать по новому порядку полей. Не редактируйте runtime внутри исторических результатов и не заменяйте записанные там хеши новыми. Исторический и текущий runtime проверяются в разных процессах.
