## Что ограничено

Матрица выхода имеет порядок **P[мышца, нейрон]**. Строка 0 — сгибатель, строка 1 — разгибатель; столбцы 0/1 — соответствующие мотонейроны.

| Поле JSON | Индекс в 52-параметрическом геноме | Связь | Область |
|---|---:|---|---|
| `output.P.0.0` | 48 | Нейрон 0 → сгибатель | `[0, 2]` |
| `output.P.0.1` | 49 | Нейрон 1 → сгибатель | `[0, 0.1)` |
| `output.P.1.0` | 50 | Нейрон 0 → разгибатель | `[0, 0.1)` |
| `output.P.1.1` | 51 | Нейрон 1 → разгибатель | `[0, 2]` |

В `genome_cfg.json` верхняя граница перекрёстных весов записана как `0.09999999999999999` — ближайшее представимое `float64` ниже `0.1`. Начальные значения равны нулю, масштаб линейный. Прямые связи начинаются с 1. Ограничение наследуется всеми профилями A/B/C, обеими стадиями C и зеркальным кодеком. Нормализация, мутация и отражение используют эти границы; штраф в fitness не добавляется. Значение ровно `0.1` недопустимо.

Абсолютное ограничение перекрёстных весов само по себе не гарантирует активность обоих нейронов, преобладание прямого пути или одновременные спайки. Поэтому рядом с качеством управления измеряется активность; это согласованный диагностический показатель, а не дополнительный критерий отбора.

## План нового sweep

- **7 базовых профилей:** A fast/slow, B fast/slow, C fast/slow/mirror. Каждый: 50 особей, 200 поколений, вероятность мутации 0,3; seed 42 для A/B и 43 для C.
- **36 fast-запусков:** отдельно для A, B и C все сочетания 200/500/1000 поколений × seed 42/43 × вероятность мутации 0,1/0,3. Популяция 50 во всех случаях.
- Масштаб мутации: 0,20 → 0,015; валидация каждые 20 поколений, а также в первом и последнем.
- A/B обучаются совместно. C fast: таблица → ограниченный МНК → полином; общий бюджет делится на две стадии поровну. C slow/mirror: совместная оптимизация полинома и физического генома.

В сумме 43 записи о запусках и 40 разных конфигураций: три fast-конфигурации базовой серии также встречаются в sweep. Это не 43 независимых повторения. Никакой запуск не использует победителя другого для инициализации. Выбор fast-победителя производится только после оценки заданной сетки, по **максимальному валидационному fitness**. Прежние результаты не участвуют.

Эквивалентные последовательные команды расширенного sweep:

```bash
for task in A B C; do
  for generations in 200 500 1000; do
    python run.py sweep "$task" --profile fast --populations 50 --seeds 42 43 \
      --mutation-probabilities 0.1 0.3 --generations "$generations" --workers 10 \
      --output "results/cross_${task}/G${generations}"
  done
done
```

`study` дополнительно считает активность каждого выбранного генома на всём тестовом банке, обновляет таблицы и по завершении экспортирует семь новых контроллеров в `*/genomes/{fast,slow,mirror}.json`. Обычная команда `sweep` сохраняет обучение, валидацию и тест; для отдельного отчёта активности вызовите `activity` на нужном завершённом запуске.

## Как создаётся начальная популяция

Центр — общий контроллер из `parameters[*].value` в `genome_cfg.json` с поправками `profiles.json`. Это вручную заданные параметры, а не обученное решение. Оба нейрона начинают с `a=0.1, b=0.2, c=-65, d=2`; диагональные рекуррентные веса нулевые, перекрёстные −0,1. Мышечные времена fast начинаются с 20/20 мс, slow — с 71/130 мс. C начинает с нулевых задающих токов. Все прочие начальные значения явно заданы в JSON.

Фиксированные параметры не входят в поиск; зеркально связанные поля используют одну независимую координату. Линейный параметр кодируется как `(p-min)/(max-min)`, логарифмический — аналогично в логарифмах. При симметричных границах команд нулевой ток соответствует координате 0,5.

Для размера N и числа независимых координат d порядок случайных операций строго следующий:

1. Создать `numpy.random.default_rng(seed)` — PCG64 в зафиксированном окружении.
2. Сгенерировать **всю матрицу N × d** нормальных возмущений со стандартным отклонением 0,1, прибавить центр и отразить выходы за `[0,1]`.
3. Заменить строку 0 исходным центром. Уже сгенерированный шум этой строки расходует RNG, хотя больше не используется.
4. Заменить последние `max(1, N//4)` строк равномерными выборками в `[0,1]` из того же RNG. Их предыдущие нормальные выборки тоже были израсходованы.

При **N=50** получаются **1 исходная особь + 37 нормальных соседей + 12 глобальных равномерных особей**. Равномерность относится к нормализованным координатам; для логарифмических физических параметров это лог-равномерная выборка. Начальных особей не фильтруют по fitness. Отражение: `r=x mod 2; R(x)=r при r<=1, иначе 2-r`; это не обрезание значений. Нулевой центр перекрёстных P остаётся допустимым, остальные выборки ограничены новым узким диапазоном.

В staged C первая таблица обучается от общего контроллера. Её лучший по валидации геном передаёт физические параметры второй стадии; только токи таблицы приближаются двумя полиномами (`scipy.optimize.lsq_linear`, `tol=1e-12`, ограниченные коэффициенты). Вторая популяция создаётся тем же правилом вокруг **результата этой первой стадии**, с перезапуском PCG64 на том же seed и нового мутационного расписания. Это часть обучения с нуля. Индекс поколения в итоговом staged-результате относится к полиномиальной стадии.

## Как искался лучший геном

Каждое поколение оценивается на неизменном обучающем банке. Размножение использует **только обучающий fitness**:

1. Сохранить `max(1, ceil(0.05*N))` лучших без изменений — 3 при N=50; равные оценки сохраняют стабильный порядок.
2. Для каждого оставшегося места с вероятностью 0,05 создать равномерного иммигранта. Иначе выбрать двух родителей независимыми турнирами по три индекса с возвращением.
3. Для каждой координаты смешать родителей с `alpha ~ Uniform(-0.15,1.15)`. Независимо с заданной вероятностью p добавить `Normal(0,sigma)` и отразить границы.
4. Уменьшать sigma по косинусу от 0,20 до 0,015. Поколение 1 — оценка начальной популяции; G поколений содержат G−1 переходов размножения. Изменение G меняет расписание с самого начала, поэтому длинный запуск не является простым продолжением короткого.

Валидация проверяет исходный центр (поколение 0), всю популяцию в поколении 1, каждые 20 поколений и последнее поколение. Победитель заменяется только при **строго большем** fitness. При равенстве внутри популяции выбирается первый индекс. Итоговым может стать ранний кандидат, а не чемпион последнего поколения.

После фиксации генома вычисляются тест и повторная оценка обучения. Все три столбца результатов относятся к **одному и тому же** геному. Между запусками выбирается максимальный валидационный fitness; при равенстве сохраняется первый в порядке G, seed, p. Ни тестовые успехи, ни показатели активности не выбирают родителей, контрольную точку или запуск.

## Сценарии, длительность и неизменённый fitness

Шаг интегрирования — 0,1 мс, длительность — 10 с, окно поздней точности — последние 2 с. Исходные углы лежат в `[-50°,50°]`, скорости — в `[-1,1]` рад/с. Банки — фиксированные латинские гиперкубы, независимые от RNG генетического алгоритма. В обучении первые три состояния заменены двумя крайними углами и центром с нулевой скоростью.

| Задача | Обучение: seed / состояния | Валидация | Тест |
|---|---|---|---|
| A/B | 2026102001 / 24 | 2026102002 / 48 | 2026102003 / 96 |
| C | 2026102201 / 8 | 2026102202 / 12 | 2026102223 / 24 |

A/B удерживают нулевой угол, приложенные токи равны нулю. C пересекает начальные состояния с 5/9/17 целями: 40/108/408 эпизодов. Табличная стадия C имеет отдельную валидацию на пяти целях (60 эпизодов); её тест не используется. Каждый эпизод сбрасывает нейронные и мышечные состояния.

Оценка эпизода содержит 0,10 за выживание, 0,30 за восстановление, 0,45 за позднюю угловую точность и 0,15 за строгий успех. В восстановлении используется `max(0, exp(-(error/15°)^2) - 0.05*min(speed²,4))`, в поздней точности — `exp(-(error/3°)^2)`. Недостающие после падения отсчёты не дают награды; знаменатели сохраняют полную запланированную длительность. Нечисленные состояния получают −1. Строгий успех требует полного эпизода и отсутствия нарушений `|error|<=3°`, `|speed|<=0.35 рад/с` после трёх секунд. Fitness банка: 0,50 среднего + 0,30 среднего худшей четверти с округлением вверх + 0,20 минимума. Поздний RMSE при падении получает штраф 90°. Низкий средний угловой RMSE сам по себе не означает строгого успеха.

`simulation.duration_s` и `simulation.fitness_window_s` задаются в конфигурации или ключами `--duration`, `--fitness-window`. Изменение окна меняет протокол: оно влияет на поздний reward и крайнюю границу установления `min(3, duration-window)`. В этой серии оставлены 10 с / 2 с.

## Диагностика активности обоих нейронов

```bash
python run.py activity --run fresh_results/expanded_A/G200/N50_p0.1_seed42
```

Команда заново проигрывает каждый **тестовый** эпизод замороженного победителя и сверяет девять исходных метрик с `test_metrics.npz`. Спайки считаются по выходам `spike_flex`, `spike_ext` на каждом шаге 0,1 мс. Сохраняется `activity.json`:

- число спайков и частота каждого нейрона за фактически наблюдавшийся эпизод;
- число спайков и частота в последних двух секундах;
- числа спайков в интервалах `(8,9]` и `(9,10]` с;
- наличие спайков у обоих за позднее окно и отдельно в каждом секундном интервале;
- число эпизодов, где один из нейронов молчит, и средняя поздняя сила каждой мышцы;
- матрица P выбранного генома и все отдельные эпизоды.

Поздняя активность считается только при полном наблюдении всего окна. Падения исключаются из её знаменателя и не записываются как «нулевая активность»; количество полных эпизодов показано явно. «Оба активны в интервале» означает хотя бы один спайк каждого в общем интервале, **не** синхронные спайки на одном шаге. Этот показатель — диагностика, не гарантия физиологической коактивации. При записи с `stride>1` подсчёт отвергается, поскольку отдельные спайки могут быть потеряны.

## Основные файлы и параметры

Вычислительная реализация по-прежнему состоит из **восьми Python-файлов**:

| Файл | Назначение |

Изменение поля `parameters[*].value` меняет исходный центр, `minimum/maximum` — область поиска, `mutable=false` фиксирует поле. Все парные характеристики должны совпадать при зеркальной симметрии. Геометрия и A=0,37 фиксированы. Сохранённый геном содержит собственную конфигурацию; изменение соседнего JSON не меняет его динамику.

## Проверки и сохраняемые артефакты

```bash
python verify.py --training --population 3 --generations 2 --workers 2 --directory results/repeatability --output training_verification.json
# После завершения study и локального создания reference-массивов:
python verify.py --workers 8 --output verification.json
```

Первая команда повторяет семь малых поисков на **полных 10-секундных банках**, с разным числом потоков. Она проверяет начальные/конечные популяции, RNG, банки, геномы, истории и метрики; это техническая проверка, не оценка качества. Полные 200/500/1000-поколенные поиски пока не объявляются повторёнными. Фиксированного seed недостаточно для обещания битового совпадения между произвольными CPU/компиляторами; используйте записанное окружение.

Каждый run сохраняет `genome_cfg.json`, `training.json`, `provenance.json`, `source_snapshot.zip`, `best_genome.json`, `result.json`, `selected_training.npz`, `test_metrics.npz` и, в этой очереди, `activity.json`. Внутри `training/` либо `table/` и `polynomial/` находятся `initial_genome.json`, `initial_population.npz`, `cases.npz`, `history.csv`, `validation_history.csv`, `validation_*.npz`, `selected_validation.npz`, `checkpoint.npz`, `final_population.npz`. Состояния RNG и порядок особей сохранены. Тренировочные коды и effective-конфигурации фиксируются хешами до вычислений.

`reset_20261116.json` содержит только перечень удалённых прежних файлов/папок и их размеры; старых геномов и результатов в нём нет. Численные результаты новой серии будут доступны в `fresh_results/`. Лицензия GPL-3.0 находится в `LICENSE`.
