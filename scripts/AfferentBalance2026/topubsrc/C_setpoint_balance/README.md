# Эксперимент C: Удержание разных заданных углов, таблица токов → полином

Одна нейронная сеть для пяти обучающих целевых углов −45…45°. Fast-профиль использует staged: сначала таблица токов, затем ограниченный МНК и совместная оптимизация полинома второй степени и сети. Полный бюджет G делится поровну между двумя стадиями.

Все команды ниже выполняются **из родительской папки `topubsrc`**, а не из `C_setpoint_balance`. Из этой папки сначала выполните `cd ..`. Окружение и полный алгоритм описаны в [общем README](../README.md).

```bash
python -m pip install -r requirements-reproducible.txt
python run.py check C --profile fast

# Проверка плана: 9 размеров × 9 бюджетов × 2 seed = 162 запуска.
python run.py grid --experiments C --population-range 10 50 5 --generation-range 100 500 50 --seeds 42 43 --mutation-probability 0.3 --jobs 2 --workers 10 --output results/C_grid_20261117 --plan-only

# Полная сетка этого эксперимента, обучение с нуля:
python run.py grid --experiments C --population-range 10 50 5 --generation-range 100 500 50 --seeds 42 43 --mutation-probability 0.3 --jobs 2 --workers 10 --output results/C_grid_20261117

# Состояние и текущие лучшие гиперпараметры:
python run.py status --output results/C_grid_20261117

# Отдельный поиск с указанными гиперпараметрами:
python run.py train C --profile fast --population 30 --generations 300 --seed 42 --mutation-probability 0.3 --workers 10 --output results/C_N30_G300_seed42
```

В текущем расчёте B и C объединены одной командой `grid --experiments B C` в `results/bc_grid_20261117`; для проверки именно этой очереди используйте `python run.py status --output results/bc_grid_20261117`. Отдельная команда выше воспроизводит только C. Совместный и отдельный варианты не нужно запускать одновременно для одной и той же сетки.

Оси сетки: популяции 10…50 с шагом 5, поколения 100…500 с шагом 50, seed 42 и 43, p=0,3. `--jobs` задаёт число независимых поисков одновременно, `--workers` — потоки Numba на поиск. Каталог результата должен быть новым. Инициализация: одна общая особь, `max(1,M//4)` равномерных особей, остальные — гауссовы отклонения σ=0,1 с отражением в [0,1]. Начальных архивных контроллеров нет.

Область генома: четыре веса от афферентов II в ±50; обе мышечные N изменяемы в [1,40]; перекрёстные P строго <0,1. Лимит частоты — каждый ISI ≥10 мс на всём эпизоде. Нарушение получает отрицательную оценку; уравнения нейронов не меняются. Динамика: 10 с, окно точности: последние 2 с. Параметры находятся в `genome_cfg.json`, профили — в `profiles.json`, базовые настройки обучения — в `training.json`.

Лучшие геномы сохраняются **во время обучения**: `training/best_genome.json` для B, `table/best_genome.json` и `polynomial/best_genome.json` для staged C. Каждый новый рекорд по валидации сохраняется ещё и как `best_genomes/gXXXX_genome.json` внутри соответствующей стадии; `selection.json` содержит гиперпараметры, путь и хеш. Поколение 0 сохраняется сразу, последующие проверки — на 1-м, каждом 20-м и последнем поколении стадии. Все улучшения перечислены в `best_history.csv`.

`leaderboard.json/csv/md` в корне сетки показывает лидеров и настройки поиска; `comparison.csv/json` и `RESULTS.md` — все завершённые запуски с train/validation/test. Промежуточный лидер помечен как `running`, итоговый — `completed`. Выбор выполняется по валидации; test не влияет на отбор. Для C в общий рейтинг входит только полиномиальная стадия. JSON-список `completed_leaders` позволяет отдельно посмотреть победителей только среди завершённых запусков.

После завершения допустимый на валидации победитель этой сетки появится в `genomes/fast_grid_rate100.json`. Загрузка динамики:

```bash
python run.py simulate C --genome C_setpoint_balance/genomes/fast_grid_rate100.json --angle -30 --target 45 --output results/C_grid_replay
```

В `explore.ipynb` можно указать тот же путь в `GENOME_PATH` или путь к промежуточному снимку. Каждый сохранённый геном содержит свою конфигурацию.

## Тестирование итогового генома полной сетки

Выбран по валидации запуск с популяцией 40, общим бюджетом 400 поколений (200 таблица + 200 полином), seed=42 и p=0,3; лучший полином найден на поколении 200 второй стадии. Полные 10 с выдержали 201/408 эпизодов, строгий успех — 0/408. Средняя поздняя RMSE среди завершённых эпизодов — 9,216°, а метрика по всему банку со штрафом 90° за ранние падения — 50,202°. В трёх тестах второй нейрон нарушил ограничение ISI: максимальная мгновенная частота 1428,57 Гц, поэтому fitness тестового банка равен −14,285714. На train/validation нарушений частоты не было. Ограничение реализовано в отборе и не подавляет спайки физически; переносимость на новые состояния не гарантирована. Геном остаётся победителем по валидации, но тестовую проверку качества и частоты он не прошёл; замены по результатам test не проводилось.

Команды из `topubsrc`:

```bash
# Повтор всех 504 тестовых эпизодов экспортированных B и C, без обучения:
python verify.py --catalogue results/bc_grid_20261117/published_results.json --workers 8

# Все тесты C с полным подсчётом спайков и проверкой сохранённых метрик:
python run.py activity --run results/bc_grid_20261117/expanded_C/G400/N40_p0.3_seed42
```

`verify.py` заново формирует test-банк из сохранённой конфигурации, рассчитывает динамику и сравнивает её метрики с зафиксированными массивами. `status: passed` относится к воспроизводимости; поле `success` сообщает число эпизодов, прошедших критерий управления. Для этих геномов повтор всех 504 эпизодов дал нулевое расхождение метрик, но строгий успех остаётся нулевым.

`activity` отдельно пересчитывает тестовые эпизоды C с шагом записи 0,1 мс, проверяет метрики и сохраняет частоты, минимальные ISI и нарушения в `results/bc_grid_20261117/expanded_C/G400/N40_p0.3_seed42/activity.json`. Данные качества — в соседнем `result.json`. Успех требует удерживать ошибку в пределах ±3° и |ω|≤0,35 рад/с с 3-й секунды до конца 10-секундного эпизода, а также соблюдать ограничение частоты.
