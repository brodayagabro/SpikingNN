# Служебные утилиты

[English](README.en.md) · [Проект](../README.md)

Здесь находятся общие помощники и команды обслуживания проекта.
Запуск опытов остаётся в `experiments/A_balance`, `B_balance`, `C_setpoint_balance` и `D_trajectory`,
редактирование рисунков — в [тетрадке статьи](../report/article_figures.ipynb).

| Файл | Назначение |
|---|---|
| [select_sweep_winner.py](select_sweep_winner.py) | Выбор победителя завершённой серии B по валидации, аудит и полные повторные траектории. |
| [analyze_joint_sweep.py](analyze_joint_sweep.py) | Аудит поколений и динамики обоих победителей C, тепловые карты валидации, RMSE геномов и сводка RU/EN. |
| [compare_muscle_relaxation.py](compare_muscle_relaxation.py) | Сравнение заранее выбранных геномов двух серий C на одном тестовом банке; константы релаксации, разброс сил и осциллограммы без сглаживания. |
| [validate_layout.py](validate_layout.py) | Проверка структуры опытов, конфигураций, тетрадок и документации. |
| [analyze_unscaled.py](analyze_unscaled.py) | Проверка исторической серии без ×10 и сборка её отчёта. |
| [runtime_support.py](runtime_support.py) | Пути к сохранённым результатам, загрузка и проверка неизменяемого численного ядра. |
| [layout.py](layout.py) | Пути к изображениям и архивным исходникам, проверка контрольных сумм. |

Команды из корня репозитория SpikingNN:

```bash
.venv/bin/python scripts/AfferentBalance2026/tools/validate_layout.py
.venv/bin/python scripts/AfferentBalance2026/tools/analyze_unscaled.py --help
```

Пути определяются относительно исходников и не зависят от рабочего каталога.
Исторический анализ требует соответствующих данных, ранее перенесённых
в системную корзину; перенос утилит их не восстанавливает.

При импорте из других модулей используйте пакет
`scripts.AfferentBalance2026.tools`. Исключения каталогов из сбора тестов
заданы в [pytest.ini](../pytest.ini); настройка путей для тестов — в
[tests/conftest.py](../tests/conftest.py).

Для C сначала выполните `experiments/C_setpoint_balance/sweep_diagnostics.py <каталог sweep>` после завершения обучения, затем `tools/analyze_joint_sweep.py <каталог sweep>`. Второй шаг сверяет все траектории и обновляет указатель тетрадки только после успешного аудита.

Для D: `experiments/D_trajectory/audit_trajectory.py <каталог серии D> --workers 18`. Результат записывается в `audit.json`; архивные источники не изменяются. Для локальной проверки структуры с пользовательским выводом в тетрадках используйте `validate_layout.py --allow-notebook-outputs`.

## Проверка прежних геномов после исправления момента

`recheck_tensile_genomes.py` проверяет неизменённые победившие геномы A/B/C/D на исходных тестовых банках, сетке начальных условий 10×10 и состояниях вблизи цели. Одинаковые копии проверяются один раз; метрики, траектории и фазовые портреты сохраняются отдельно в `results/` каждого опыта. Обучение и замена победителей не выполняются. Стандартное имя каталога — `torque_sign_check_20261026`; существующие каталоги не перезаписываются.

```bash
.venv/bin/python scripts/AfferentBalance2026/tools/recheck_tensile_genomes.py --tag torque_check_repeat
```

## Переобучение с мышечными временами ≥50 мс

`prepare_muscle_times.py --genome OLD.json --config EXPERIMENT/genome_cfg.json --output NEW_INPUTS` сохраняет исходник и создаёт четыре допустимых старта: clipped/reference, с компенсацией установившихся коэффициентов передачи и без неё. Опорные времена читаются из нового конфига (в текущей серии 71/130 мс).

`retrain_tensile.py` обучает самодостаточный подготовленный геном и сохраняет все популяции. `retraining_figures.py --experiment ИМЯ_ПАПКИ --run КАТАЛОГ_ЗАПУСКА` независимо пересчитывает победителя, фазовые сетки и примеры сигналов. `finalize_retraining.py` выбирает завершённых победителей по проверке и обновляет входы тетрадок, сохраняя прежние актуальные файлы. Текущая серия — `muscle_tau50_20261026`; точные команды и смысл ключей приведены в [отчёте](../report/REPORT.md).
